# MASCOT (Multi-Agent System for Competency Optimization and Team distribution)

**MASCOT** — это интеллектуальная мультиагентная система (MAS) для оценки компетенций сотрудников, анализа проектных требований и автоматического подбора оптимальных команд. Система собирает «цифровой след» сотрудников из корпоративных систем (Git, Jira, LMS, HR), формирует профиль компетенций и на его основе распределяет людей по проектам с учетом математических весов и бизнес-ограничений.
## **Текущее состояние:**
Проект находится в стадии активной разработки. Реализовано ядро системы и базовые модели данных. Большинство модулей агентов, интеграция с LLM, база данных и API пока находятся в виде пустых файлов (заглушек) или требуют доработки.

##  Запуск (Только проверка текущего кода)
На данный момент система не имеет API или UI. Доступны только консольные скрипты для проверки логики.
1.  **Установка зависимостей:**

```bash
python -m venv .venv
source .venv/bin/activate  # Для Windows: .venv\Scripts\activate
pip install -r requirements.txt
```
2.  **Проверка целостности данных (JSON):**
    Запускает валидацию тестовых сотрудников и проектов из папки `data/raw/`.
```bash
python -m scripts.check_data
```
3.  **Проверка базового подбора команды:**
    Запускает сценарий, который берет первый проект, сопоставляет его с сотрудниками и выводит текстовый отчет в консоль.
    *(Примечание: перед запуском убедитесь, что `distribute_team.py` сохранен в UTF-8, иначе скрипт упадет с ошибкой чтения)*.
```bash
python -m scripts.check_matcher
```

##  Архитектура системы
Система построена на базе собственного асинхронного ядра (шины сообщений) и разделена на четыре логических слоя:
1.  **Слой данных (Data Layer):** Подключение к Git, Jira, 1C, SAP, LMS. Парсинг цифрового следа, дедупликация и приведение к единому формату (JSON).
2.  **Аналитический слой (Analytics Layer):** Оценка Hard-Skills (код, стек), Soft-Skills (оценка 360, STAR-интервью), KPI/OKR и динамики обучения. Формирование единого профиля сотрудника.
3.  **Слой принятия решений (Decision Layer):** Оркестратор на базе LLM и Математический оптимизатор (на базе SciPy) для распределения сотрудников по проектам с максимальным покрытием требований.
4.  **Слой доверия (Trust Layer):** Обеспечение прозрачности. Провенанс каждой метрики, логирование источников, маскировка PII (152-ФЗ) и генерация человекочитаемых объяснений (Explainability).

##  Детальный статус файлов

###  Написано и работает (Ядро и модели)

*   **`core/message.py`**: Модель `AgentMessage` на Pydantic для обмена данными через шину.
*   **`core/message_bus.py`**: Асинхронная шина сообщений (брокер), поддерживает адресную отправку и broadcast, изолирует ошибки агентов.
*   **`core/base_agent.py`**: Абстрактный базовый класс агента с автоматической регистрацией в шине.
*   **`trust_layer/metric.py`**: Модель `Metric`. Реализует хранение значения, источника, периода и оценки уверенности (провенанс метрики).
*   **`agents/data_layer/trace_parser.py`**: Асинхронный агент, принимающий сырые данные, валидирующий их через Pydantic и передающий дальше в шину.

###  Работает, но требует рефакторинга (Временные решения)
*   **`agents/data_layer/integrator.py`**: Загружает JSON в модели. *Проблема:* Путь к файлам вычисляется "хардкодом" относительно файла (`parents[4]`). Требует выноса в `config/settings.py`.
*   **`agents/data_layer/scale_validator.py`**: Проверяет уровни навыков (0.0 - 1.0). *Проблема:* Константы захардкожены, требуется вынос в конфиг.
*   **`pipelines/distribute_team.py`**: *(Внимание: в репозитории файл сохранен в неверной кодировке, отображается как binary)*. Содержит базовую логику сопоставления (матчинга) сотрудников и требований. Написан для быстрой проверки работоспособности, не использует математический оптимизатор.
*   **`storage/models.py`**: Содержит доменные модели (`Employee`, `Project`, `TeamRecommendation`, `EmployeeProfile`). *Проблема:* Модели есть, но фактического подключения к SQLAlchemy/PostgreSQL пока нет.

###  Пустые файлы / Заглушки (Требуют написания)
*   Все файлы в `config/` (нет загрузки `.env`).
*   Почти все агенты в `analytics_layer/` и `decision_layer/` (нет логики оценки и оптимизации).
*   Модуль `llm/` (нет клиента для GigaChat и парсеров ответов).
*   `storage/database.py` и `vector_db.py` (нет работы с PostgreSQL и ChromaDB).
*   `api/` и `ui/` (нет веб-сервера и интерфейса).
*   `tests/` (нет покрытия тестами).
##  Принципы архитектуры (Заложенные в основу)
1.  **Асинхронность:** Обмен данными между компонентами происходит через `asyncio` и `MessageBus`.
2.  **Провенанс:** Любая рассчитанная метрика оборачивается в класс `Metric`, содержащий информацию о том, откуда она взялась.
3.  **Изоляция LLM:** В планах вынести все взаимодействия с ИИ в отдельный изолированный модуль `llm/` с текстовыми файлами промптов.

## Блок тестирования:
- Создайте и активируйте виртуальное окружение(рекомендованно для каждого проекта)
